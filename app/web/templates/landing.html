How every submission is handled

  1. 01

    Receive

    An operator submits one or more untrusted business documents for inspection.

  2. 02

    Isolate

    Parsing and detection happen inside a disposable, network-disabled worker — never inside the trusted application.

  3. 03

    Explain

    Structural findings are translated into bounded, human-readable evidence — never a raw, unexplained score.

  4. 04

    Decide

    A deterministic policy produces exactly one of four outcomes.

    Allow
    DocGuard did not observe risky characteristics covered by the configured model.
    Review
    The document requires human attention before release.
    Quarantine
    Significant risk or incomplete analysis requires containment.
    Block
    A hard security rule prevents release. Operators cannot override BLOCK in this release.
  5. 05

    Reconstruct, when eligible

    Eligible PDFs can be rebuilt through Content Disarm and Reconstruction into a separate derived artifact, fully re-analyzed before it is ever offered for release.

A real trust boundary, not a black box

Every submission crosses from the trusted application into a disposable worker that can only ever report back a bounded, versioned result — never raw access to anything it touched.

Technical overview — isolation, policy, and reconstruction details

All hostile parsing happens inside the disposable worker shown above — never in the trusted application. A deterministic policy evaluation turns the observed structure into one of the four decisions below. Eligible PDFs can additionally go through PDF Content Disarm and Reconstruction (CDR), which reconstructs a derived, sanitized document and is always followed by mandatory re-analysis of that output before anything is approved for release. An ALLOW decision means no covered risky characteristic was observed under the active policy — it is not a guarantee that a document is benign.
